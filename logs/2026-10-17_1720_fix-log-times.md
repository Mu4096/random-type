# fix-log-times
- 状態: 完了
- 開始: 2026-10-17 17:20

## 目的
ログのファイル名・開始・経過の時刻が実際と違う（10/17 23時台などの未来の時刻になっている）ものを直し、原因を調べる。

## 経過
- 17:18 logs/ の一覧で 2026-10-17_2350・2359（2件）が未来の時刻になっているのを確認
- 17:19 Claude Code のセッション記録（~/.claude/projects/ の jsonl）から、各ログを作ったツール呼び出しの実時刻と、依頼が来た時刻を突き合わせた。間違っていたのは8件
  - 10/16 start-keys・register-decline（経過のみ）・favicon・remove-subtitle、10/17 rank-bubble・grade-looser・normal-desc-period・ogp
  - 初日（16:32〜18:05）のログは依頼の時刻と一致しており問題なし
- 17:20 ファイル名・開始・経過の時刻を実時刻に直し、docs/history.md のログへのリンクも新しいファイル名に合わせた
  - 開始はユーザーの依頼が来た時刻、経過はその作業をしたツール呼び出しの時刻
- 17:22 ユーザーの OK を受け、CLAUDE.md の「ログ」に時刻確認のルールを追加

## 判断
- [確認済み] 再発防止として、CLAUDE.md に「ログを書く前に date で時刻を確認し、結果を見てから書く」ルールを足す
- [AI判断] ユーザーが挙げた未来の時刻の3件だけでなく、時刻が実際と違っていた過去のログもまとめて直した
- [AI判断] register-decline はファイル名・開始が正しい（Get-Date で確認していた）ので、経過の時刻だけ直した
- [AI判断] ログの中身を直すために、OK 前だが docs/history.md のログのファイル名だけ書き換えた（リンク切れになるため）

## 原因
- Claude Code に渡されるのは「今日の日付」だけで、現在の時刻は渡されない
- 作業開始時に直前のログの開始時刻（head -3）を見て、それより後になりそうな時刻を推測で書いていた。時刻を確認するコマンドを実行していないセッションがほとんど
- 推測なので、一度ずれると次々にずれた（23:45 → 翌0時台を「12:00」→ 直前より後の「23:50」→「23:59」で頭打ち）
- 時刻を確認したセッションでも、`date && cat > ログ` のように確認と書き込みを1回のコマンドでやり、結果を見る前に推測の時刻で書いていた（favicon）。grade-miss-penalty は同じ形で 23:59 と書いたが、date の結果を見て直していた
- 経過の時刻もログを作業の最後にまとめて書いたときに推測で埋めていた（register-decline はコミット 23:14 なのに経過が 23:20・23:25）
